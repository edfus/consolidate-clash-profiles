ASMR / Futu synchronization review — 2026-10-13

Status: local candidate only. Not staged, committed, pushed or deployed.
The production Clash service, QX published release and HTTPS gateway remain unchanged.
User-confirmed scope: add an independent Futu group to BOTH Clash and Quantumult X.

Behavior for review

Clash:
- Futu is a new select group. First option is the existing Proxy group; all actual
  nodes are manual alternatives. No DIRECT option is introduced in Futu.
- The existing 47 Futu/Moomoo domain rules and four process rules now target Futu.
- meta/mobile/tun are synchronized. Node selection, ASMR, DNS and Anthropic filters
  are unchanged. ToDesk DIRECT still precedes Anthropic, ASMR and Futu.

Quantumult X:
- ASMR is a static/manual group, containing only actual HK/JP nodes, HK first.
  If neither region exists, the only candidate is built-in reject.
- Futu is a separate static/manual group. Built-in proxy is first, then all 140
  embedded nodes as manual alternatives; no direct option is added.
- 47 Futu/Moomoo destination rules and the asmr.one suffix rule are synchronized.
  QX output explicitly omits the four Clash PROCESS-NAME entries. Unattributed
  pure-IP Futu connections retain existing routing; no shared-cloud CIDRs are added.
- Existing AI Suite and the two-node Anthropic selector are retained.
- Existing policy definitions, local/remote rules, node payloads, general, DNS,
  rewrite and MITM sections were compared against the currently published QX
  configuration. They are unchanged outside the new app groups/resource/block.

Rule priority and publication

The new public Apps.list has 64 rules:
  2 ToDesk destination bypasses
  14 existing QX Anthropic rules (scope preserved; no new shared telemetry domains)
  1 ASMR domain suffix
  47 Futu destination rules

It is the FIRST inserted QX remote filter, without force-policy because the
individual rules target different groups. Existing remote resources retain
settings and relative order. The same block is embedded ahead of existing local
rules. If Apps.list is unavailable while a conflicting inserted remote resource
remains active, the embedded copy cannot guarantee overriding it; Apps.list must
be published and verified before activating the private QX candidate.

The public rule file is generated from existing public destination files and
contains no nodes, passwords, authenticated URLs or private server configuration.
The existing public Anthropic.list is not modified.

Two serving layers need the new exact path:
- The QX Caddy side service's whitelist adds /quantumultx/Apps.list.
- The actual 8443 HTTPS gateway currently exposes only the old Anthropic resource.
  A PRIVATE gateway candidate adds only an exact Apps.list reverse proxy to the
  existing QX side service. Both containers already share the caddy network.
  Existing HTTPS authentication, TLS settings and all old gateway routes must
  remain identical. This private file is ignored and must never be committed.
- Private QX delivery is mounted as the generated parent directory, so a current
  symlink switch is visible without recreating the HTTPS gateway.
