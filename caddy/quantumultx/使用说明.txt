Quantumult X：Anthropic 独立分流

使用
1. 备份当前 Quantumult X 配置，导入 quanx.anthropic.conf，保留或补回自己的节点订阅。原链接的 server_local 和 server_remote 都为空，此文件不附带节点。
2. 在策略中分别进入 Anthropic 和 AI Suite，选择不同的实际代理节点。两个组均通过 server-tag-regex=.* 列出节点，不再共同引用 Outside。
3. Anthropic 如需沿用 Clash 的选择，请手动选择洛杉矶 02 或 06 节点。因为未提供 Quantumult X 中的实际节点名称，此版本不强制名称筛选。
4. 在 Quantumult X 请求记录中访问 Claude、OpenAI，确认分别命中 Anthropic、AI Suite，并核对所选节点。

改动
保留原有所有远程 Filter、DNS、重写及其余配置。在 filter_local 顶部加入 14 条 Anthropic 规则，覆盖专属域名、认证/CDN 主机和官方 API 入站 IPv4/IPv6 网段。普通远程 Filter 中原有的 Claude 规则仍保留，由本地专用规则优先接管。不要为原 AI Suite 远程 Filter 设置 force-policy=Anthropic，否则其他 AI 服务也会被改路由。

边界
anthropic.com 子域（包括 statsig.anthropic.com）走 Anthropic。共享 Sentry、Statsig 等域名继续遵循原有规则；仅靠域名无法可靠区分同一共享主机上的不同服务，因此没有把整个 sentry.io 等域名划入 Anthropic。纯 IP 规则仅覆盖官方公布的入站 API 网段，不能识别所有共享 CDN IP 或第三方云端 Claude 接口。已有 DNS/IPv6 设置保持原样。

Anthropic.list 是同内容的独立规则文件，便于将来托管为远程 Filter；当前完整配置已内嵌这些规则，不需要重复导入。普通远程 Filter 不应启用 inserted-resource=true 越过这些本地规则。

验证
已检查除 policy/filter_local 外各节逐字保持一致，检查域名正反例、IPv4/IPv6 边界及 final 规则位置。尚未在 Quantumult X 客户端完成实机验证。原来源在线配置未修改。此副本通过 https://ladyfirst.uk/quantumultx/quanx.anthropic.conf 分发。
